## 一、运行边界

### 目录职责与依赖约束

- `src/ui`：共享 React + TypeScript 界面、交互流程与前端状态；浏览器预览和桌面 WebView 复用，原生命令及事件由 `adapters/desktop.ts` 封装，各功能适配器决定浏览器能力边界。
- `src/app`：Tauri 桌面入口，负责 IPC、服务组装、AI 网络请求、存储线程协调，以及 Keychain、系统语音、原生音频采集等本机能力。它并非只有命令转发，也包含请求校验和生命周期逻辑；Cargo 包名为 `quicklang-app`，库名为 `quicklang_app`，可执行程序为 `quicklang`。
- `src/server`：独立 Axum HTTP 服务骨架，不是当前桌面功能的 Web 后端，也不代理桌面 AI 请求。
- `src/crates`：按职责划分的可复用 Rust 领域、用例、端口和适配器。`domain` 不依赖 UI、desktop、server 等入口，共享 crates 不反向依赖入口。

依赖方向由各 `Cargo.toml` 和根 workspace 明确：`application` 依赖领域、调度器和存储端口，`storage-seekdb` 实现存储端口，桌面入口组装它们；`server` 是独立构建入口。React 中的学习会话、听力轮次和同声翻译处理队列仍属于前端逻辑，不能将共享 crates 的存在理解为所有业务都在 Rust 中执行。

### 桌面应用：React + Tauri 2 + Rust

`src/ui/src/app/App.tsx` 组织用户选择、词库、学习、听力、会话、同声翻译和设置页面。启动入口先加载 seekdb 应用状态，再组合 AI 配置上下文、语音启动检查及学习者选择；`SpeechStartup` 执行后台非阻断检查，不是必须完成后才能进入页面的启动关卡。同声翻译首次打开后保持挂载，切换普通页面只隐藏组件，不停止采集；切换学习用户会重新挂载用户页面并触发旧会话清理。

前端通过 `adapters/desktop.ts` 封装的 `invokeDesktop`/`listenDesktop` 使用 Tauri 命令与事件，命令由 `src/app/src/lib.rs` 注册。桥接可用仅表示处于 Tauri 环境，不保证系统权限、存储或服务就绪。现有命令已经覆盖：

- 运行状态、拼写评估、复习状态读取与评分提交。
- 听力资料仓库。
- AI 配置列表、保存、删除、激活、凭据解析及凭据重置。
- 系统语音列表、音频生成、增强语音下载及下载偏好。
- AI 对话、会话录音转写、听力音频转写。
- 同声翻译采集启动/停止、分段转写、文本翻译与摘要；音频和采集错误通过事件返回主 WebView。

**注意：存在 IPC 命令不等于所有界面已经使用它。** 当前学习页面的位置、统计和设置主要走前端 `useSaved`；Rust 复习事务链路与这些页面进度不能画成同一条已经贯通的数据流。

### 浏览器预览：明确区分能力

`src/ui/src/adapters/runtime.ts` 在浏览器返回 `browser_preview`，拼写评估使用 TypeScript 本地实现；桌面模式调用 Rust。`src/ui/src/adapters/seekdb.ts` 明确要求桌面环境，不会把数据库提交静默降级成 localStorage 写入。

浏览器预览不提供持久化替代品：原生 seekdb 不可用时，应用状态加载门禁显示错误，不通过 localStorage 或 IndexedDB 绕过。独立模块的临时内存预览不等于持久化成功；原生数据库、Keychain 和系统语音等能力需分别检查，不能把浏览器预览视为完整桌面运行环境。

### 服务端与同步：独立预留，不在当前桌面主链路中

`src/server/src/main.rs` 仅监听 `127.0.0.1:4318`。`src/server/src/lib.rs` 的 `/health/live` 返回活性状态；`/health/ready` 和其他路由返回 503 `DB_NOT_CONFIGURED`。

`src/crates/sync-core/src/lib.rs` 实现推送批次结构及校验，没有完整网络同步、身份认证或冲突合并链路。因此不要把它画成已经连接桌面和 OceanBase 的生产服务。移动入口同样不代表移动端能力已经全部实现。

## 二、持久化数据统一进入 seekdb

### 应用状态

用户档案、学习设置与进度、词库编辑、会话文字记录和设备语音设置等持久化状态统一写入 seekdb 的 `ql_app_state`，以键和字符串值保存。前端启动先完成状态加载，再开放依赖这些状态的界面；通过 `app_state_list` 读取、`app_state_write` 原子批量写入，等待提交成功后才确认操作成功。按用户区分键名不等于系统级认证或安全隔离。模块级说明见[模块文档](./modules)。

不再使用 localStorage 或 IndexedDB，也不读取、导入或清理旧浏览器存储作为迁移步骤；存储不可用时明确报错，不退回浏览器持久化。

### 同声翻译历史

同声翻译通过 `interpretation_repository` 把会话、分析运行以及分段 WAV 音频、转写和翻译写入 seekdb 专用会话/分段表。音频使用 Base64 传输，持久化音频位于数据库内，不依赖浏览器 Blob 存储或外部音频文件。前端先等待音频提交成功，再进入串行 AI 处理队列；会话不保存模型密钥。历史与其他数据库数据共用 `QUICKLANG_DATA_DIR` 指定的数据目录。

### 桌面嵌入式 seekdb

`src/app/src/storage.rs` 的 `StorageService` 使用容量为 32 的同步请求队列，把数据库访问交给专属线程。原生连接在该线程创建和使用，不跨线程共享原生句柄。

实际适配器为 `src/crates/storage-seekdb`，承接复习、词库导入、听力、AI 配置和语音偏好等数据。默认数据路径为应用数据目录下的 `seekdb-1.4.0`，可通过 `QUICKLANG_DATA_DIR` 指定。

开发模式从 `deps/cache/seekdb-runtime` 和 `src/ui/public/content/word-library` 加载运行时及词库；发布模式从应用资源中的 `seekdb` 和 `word-library` 加载。浏览器与桌面共用这份最终词库，包含 17,844 个单词、14 本词书及 60,897 个有序成员。初始化、开发和构建不依赖上游仓库；初始化仅导入缺失记录并保留已有用户编辑。

### AI 凭据与外部服务

桌面配置元数据及加密凭据由 seekdb 存储，主密钥通过系统 Keychain 访问。桌面外部模型调用由 `coach.rs`（会话/听力/词库补词）和 `interpretation_ai.rs`（同声翻译）分别处理，超时和响应上限并不相同。浏览器请求辅助函数有 `fetch` 分支，但当前 AI 配置服务仍依赖原生数据库；“配置可列出”与“凭据可解密并成功调用”是不同状态。

会话练习录音需用户点击转写才上传；同声翻译在用户启动采集后自动上传已保存的音频分段，启用翻译时继续发送转写文本。两者不能使用同一条“录音不会自动上传”的描述。

客户端使用 OpenAI 兼容协议，可直连兼容服务，也可连接单独部署的 LiteLLM Proxy。网关不是应用内置进程，填入网关地址不会自动安装或启动它。网关部署方式见[大模型统一接入](../development/0.1/llm-gateway)，凭据解析流程见[模块说明](./modules)。

## 三、数据库与词库采用两阶段就绪

数据库打开后，按构建时从 `src/schema/*.sql` 自动收集并嵌入的 `CREATE TABLE` SQL 逐表检查：已存在则跳过，缺失则依次创建并立即复查；所有必需表的检查与补建均成功后，才设置 `phase = ready`、`persistence_ready = true`。新增 SQL 文件不需要手动注册或修改初始化代码。不维护旧版 schema 兼容链，也不自动 `ALTER`、重建或修复已有表结构。DDL 可能自动提交，失败后再次启动会重新检查并补齐缺表，不能宣称整个建表批次原子回滚。词库仍可能处于 `validating` 或 `importing`。

词库校验在线程外完成文件工作，导入批次回到数据库所属线程执行，并在批次之间处理请求。这样词库尚未完成甚至加载失败时，AI 配置、听力仓库和语音偏好仍可继续使用。

复习读取与评分额外检查 `library_ready`：初始化期间返回 `LIBRARY_NOT_READY`，词库失败返回 `LIBRARY_UNAVAILABLE`。队列满或工作线程断开返回 `DB_UNAVAILABLE`。不能只凭数据库已就绪就宣称词库已可用。

## 四、Rust 业务层的依赖方向

- `domain`：共享领域结构、评分类型、复习状态和统一错误。
- `scheduler`：根据旧状态、评分和时间计算下一次复习状态。
- `typing-engine`：拼写规范化、差异及建议评分。
- `storage-api`：仓库、时钟及提交结果接口。
- `application`：组合领域、调度和仓库接口，实现复习用例。
- `storage-seekdb`：数据库适配器，落实仓库及其他存储能力。
- `desktop`（crate `quicklang-app`）：组装服务，暴露 IPC，接入系统与外部 AI 能力。

`application::rate_card` 校验事件标识，先检查幂等事件，再检查预期版本，调用调度器，最后通过仓库提交复习事件和新状态。重复事件可返回 `AlreadyApplied`；复用事件标识但卡片 ID 或评级不一致返回 `EVENT_CONFLICT`；版本过期返回 `SESSION_STALE`。

这条链路已经实现，但不能据此声称当前所有学习页面都已经通过该调度器保存进度。
