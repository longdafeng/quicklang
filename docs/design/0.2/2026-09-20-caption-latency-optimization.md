# 实时字幕延迟优化与验证（2026-09-20）

## 已完成的行为变化

- 原文使用最新滚动文字窗口，最多约 24 词 / 160 Unicode 码点，结果到达即更新。旧页不再要求停留 1–5 秒；面板布局仍由原生字体度量决定。窗口之外的旧文字不保证继续展示。
- 本地识别默认同时启用 `volatileResults` 与 `fastResults`。设置进程环境变量 `QUICKLANG_CAPTION_FAST_RESULTS=0` 可回到普通模式，便于对照和质量排查。
- 翻译可在临时识别中检测到短分句、且该分句持续稳定约 450 ms 后开始；最终片段立即拆分。标点优先，较长英文按最多 12 词拆分。没有可靠词时间戳时仍沿用源音频范围，不伪造每个分句的音频起止时间。
- 翻译使用 SSE 逐步显示，同一请求的增量更新复用一个显示身份，不重复排队。服务返回完整 JSON 时也兼容；明确拒绝流式且说明不支持时尝试一次非流式回退。
- 保留一个活动请求和最多四个短分句待处理。更新的音频范围淘汰旧的待处理范围；过载仍可能跳过内容，因此不是会议逐字记录模式。源文字被修订、切换配置、停止会话均取消旧请求；配置代次、请求顺序及更新修订号阻止过期覆盖。
- HTTP Client 复用连接池；本机服务使用独立的无代理客户端，避免环境代理影响 localhost 连接。

## 持久化耗时日志

默认位置：`~/Library/Logs/io.github.longdafeng.quicklang/caption-timing.jsonl`。

后台写入线程、有界队列、非阻塞投递；每文件约 10 MB，保留三个旧文件。队列满会计数并在后续记录报告，不阻塞采集线程。启动字幕时先验证日志文件可以打开。日志不含音频、字幕正文、模型密钥或服务 URL。

关联字段：`sessionId`、`resultId`、`requestId`、`generation`；另有音频范围、输入前沿、是否 final、是否 fastResults、时间戳和分阶段耗时。

覆盖阶段：会话准备/采集/停止、周期输入快照、每个 ASR 结果、原文入队/原生更新、前端收到结果、翻译排队/启动/首字/完成/丢弃/失败/取消、原生网络启动/首字/完成、译文面板更新。

`asr_result.elapsedMs` 是 Swift 主队列投递等待；`source_presented.elapsedMs` 是识别回调投递与原生显示更新调度的耗时。`network_*` 是自该请求启动以来的时间。`translation_started.elapsedMs` 是前端队列等待。不同阶段不能盲目相加；`source_presented` 表示原生更新调用完成附近的记录，不代表屏幕实际像素绘制时间。

输入前沿减识别范围末尾仍仅表示音频覆盖差值。未添加 VAD、没有识别器内部已消费位置，不能把静音或覆盖差值直接当成纯模型计算耗时。

查看最近会话：

```sh
python3 scripts/testing/caption-timing-report.py
```

## fastResults 同音频 ABBA 结果

macOS 本机，固定 Samantha 合成英文，175 词/分钟，约 30 秒、90 个参考词。使用同一音频文件，20 ms 音频块按真实时间推进；模型准备时间不计入首次出字。运行前确认真实字幕会话已停止。两次预跑不计入结果，以下为严格串行的 baseline → fast → fast → baseline。

| 模式/顺序 | 首结果 | 最终片段末尾至结果的中位差值 | 最大差值 | 参考词错误率 |
| --- | ---: | ---: | ---: | ---: |
| baseline / 1 | 4.000 s | 1.024 s | 3.971 s | 3.33% |
| fast / 2 | 1.102 s | 0.867 s | 1.159 s | 1.11% |
| fast / 3 | 1.098 s | 0.886 s | 1.091 s | 1.11% |
| baseline / 4 | 3.988 s | 1.025 s | 4.006 s | 3.33% |

首结果约快 2.9 秒（约 72%）。WER 仅做大小写及标点归一化，`1st` 与 `first` 仍算不同词；baseline 包含这些数字词形差异及 discuss/discussed 差异。因此这组数据不证明 fastResults 普遍更准确。清晰合成音频也不能代表口音、噪声或多人会议。

音频 SHA-256 和逐结果数据：`build/benchmarks/caption-asr/summary.json` 及同目录 JSONL。基准日志有意包含测试素材的识别文本，与日常应用的无正文耗时日志分开。

复测：先停止真实字幕会话，再运行：

```sh
python3 scripts/testing/caption-asr-benchmark.py
# 也可指定本地音频与对应参考文本：
python3 scripts/testing/caption-asr-benchmark.py --audio /absolute/input.wav --reference /absolute/reference.txt
```

测试程序在必要时准备英文系统模型资源，串行执行四次，不采集麦克风或系统声音。

## 真机与自动化验证

- 构建及本地证书签名通过，应用成功打开。
- 真机系统音频、关闭云端翻译的 smoke test 已看到字幕正常更新。落盘日志确认 `fastResults=true`，首次输入至首结果约 1.097 秒。采样 83 次原文更新，主队列投递加原生更新调度中位约 3.86 ms，最大约 16.07 ms；这是单次采样，不是长期 p95 指标。
- 此次真机播放在资源准备阶段开始，因此只验证了音频后半段；完整固定音频的识别对比以 ABBA 为准。第一次模型资源准备约 16 秒属于启动成本，不应混入稳态识别延迟。
- TypeScript 检查通过；前端全量 414 项测试通过。既有云端设置测试显式选择云端模式后继续验证设置恢复。
- Rust 桌面库 45 项通过，5 项依赖真实数据库的既有测试忽略。新增覆盖分片 UTF-8/SSE、提前显示、完整 JSON、取消竞态、持久化元数据、实时显示不等待旧页。
- Swift 严格并发、核心测试、C ABI/后台执行/快速取消生命周期测试通过。
- 外部翻译服务的真实首字延迟和准确率尚未实测；本次网络验证使用本机测试服务。长时间会议、噪声、口音及多说话人仍需后续实际使用数据。
