### 5.3 ⚠️ 关键教训：「一句话短探测通过」≠「真实任务能跑完」

这是本次任务**最贵的一条教训**，必须写进永久归档：

| 环节                 | 错误做法                                                                                                                                                                                                          | 正确做法                                                                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **探测信号**         | 派一个最小代理，只要求回复 `QUOTA-OK`，拿到响应就判定"有配额"                                                                                                                                                     | **以「该模型近期是否跑完过完整代理任务」为准**                                                                                    |
| **失败案例**         | 21:00 `QUOTA-OK` 探测：MiMo ✅、Fledge ✅<br>21:02 派**真实任务**（#54-A 导出核心 / #55-D 发布清单）→ **两者立刻 429**                                                                                            | 21:33 起改为派真实任务探测：Ling 21:35 立即 429 → **Ling 移出可派池**                                                             |
| **根因**             | 免费模型额度是**滚动窗口内的少量 token**。一句 `QUOTA-OK` 只需 ~1k token，而一个真实代理任务要**读设计文档（163KB）+ 改代码 + 跑 cargo 测试 + 迭代重试**，动辄 3M–25M token（实测单会话最高 38.3M）→ **必然超额** | 探测消耗必须与真实任务同量级，否则结论无效                                                                                        |
| **量化证据**         | 短探测会话实测 token：`探测MiMo配额` 1,337 in / 6 out / 4,096 cache；`探测Fledge配额` 6,537 / 62 / 0                                                                                                              | 真实任务会话实测 token：`#54-C` 150,741 / 42,543 / **7,902,085**；`#55-C` 485,688 / 85,859 / **38,261,242** → **相差 4 个数量级** |
| **0-token 会话证据** | 全库 **19 个会话 `tokens_input = tokens_output = tokens_cache_read = 0`**（占 80 个会话的 **23.8%**；旧快照 15 个，收尾阶段新增 4 个全部来自 00:58 复探）——即"派单成功但首 token 即被拦" | 这些会话是替补链的**全部失败点**，也是 16 次替补事件的来源 |
**最终判据（已写入探测协议）：**

> **一个免费模型算"可用"，当且仅当它跑完过一个完整的代理任务**（读文档 → 改代码 → 跑测试 → 提交 → 出报告）。只回一句话、只拿到首个 token、只成功创建会话，**都不算**。
> 本项目最终结论：**8 个免费模型中，只有 Space Bunny 满足该判据**（**24 个会话、0 次限速、0 个空跑**）；MiMo 在 23:37 曾短暂满足，23:45 即再次耗尽。**

### A.5 探测窗口结论

看板的探测协议经历了**三次判据修正**，最终判据与全部证据见本文件 **§5.2 / §5.3 / §5.4**（此处只留归档索引）：

| 阶段 | 判据 | 结论 |

> **最终判据（已写入永久归档）**：**一个免费模型算「可用」，当且仅当它跑完过一个完整的代理任务**
> （读文档 → 改代码 → 跑测试 → 提交 → 出报告）。只回一句话、只拿到首个 token、只成功创建会话，**都不算**。
> 本项目最终结论：**8 个免费模型中，只有 Space Bunny 全程稳定满足该判据**（详见 §5.3 / §5.4）。
