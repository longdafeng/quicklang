# 代码逻辑重构与回归测试增强设计稿

状态：已按批准范围完成重构与测试增强；验证结果见[实施计划与验证记录](../plans/2026-10-06-code-clarity.md)。完整 make test 的 Clippy 阶段仍受本机 AMFI 拦截。

## 目标与边界

依据全局和项目级 AGENTS.md，改善职责边界，使控制流和数据流更明确，并增强回归测试。保持现有产品行为、错误码、持久化语义和 IPC 契约；若发现并验证已有缺陷，单独说明修正内容。此次工作不修改用户真实数据，不安装应用，不删除构建缓存，不增加旧版本兼容路径。

初次检查时工作区没有未提交改动。本方案针对已检查的两个模块，不代表已完成全仓库审查。后续模块需要分别检查并制定方案。

## 方案比较

1. 推荐：按职责分阶段拆分，先处理原生存储工作线程和听力训练流程。每次拆分前用测试锁定现有行为，拆分后执行跨层回归验证。
2. 仅调整文档和命名：实现风险较低，但职责混杂和异步状态难以测试的问题仍然存在。
3. 一次性重写全仓库：涉及范围更广，但行为回归更难定位，改动也更难审阅。

## 原生存储模块设计

当前 `src/app/src/storage.rs` 同时包含服务接口、具有明确类型的请求与响应定义、工作线程启动、请求分发、用户数据版本检查、凭据失效处理和分阶段词库初始化。`start_with_keys` 同时承担启动逻辑和较大的请求分发循环。

保留 `storage.rs` 作为对外服务入口，在 `src/app/src/storage/` 下拆出私有模块：`request.rs` 负责请求与响应类型，以及拒绝版本过期的受保护请求；`worker.rs` 负责数据库启动和串行请求分发；`library.rs` 负责词库初始化和就绪状态检查。在能够明确职责和依赖的前提下，将工作线程中的备份导入和凭据解析阶段提取为独立函数。

数据库句柄仍只由专用工作线程使用。保持队列容量、就绪状态报告、写入前的 epoch 版本检查、成功导入后的凭据失效处理、已失效会话的拒绝逻辑，以及配置操作不依赖词库就绪的行为。保留响应的类型约束，不改成未经校验的通用 JSON。

测试覆盖：拒绝受保护请求时不执行回调或写入、导入成功与失败、凭据解析延迟返回、已失效会话、通道不可用或队列已满，以及词库启动和失败场景。现有标记为 ignored 的数据库测试必须通过数据库测试流程显式执行，不能仅以普通测试通过作为验证依据。

## 听力模块设计

当前 `src/ui/src/shared/features/listening/Listening.tsx` 同时包含材料列表、导入删除、训练会话界面、串行进度保存、音频播放、AI 请求取消和资源清理。

拆出 `ListeningSession.tsx` 负责训练会话展示，`useListeningMaterials.ts` 负责材料读取、导入、删除和浏览器预览音频数据，`useListeningProgress.ts` 负责排队执行进度变更，以及累计听力和口语时长。仅在能够形成职责集中、可独立测试的接口时，进一步提取播放或 AI 请求生命周期 Hook。

显式传递所属用户、存储操作和回调。进度只在持久化成功后生效。保持以下行为：保存失败时保留累计时长，部分导入失败时保留此前成功的材料，保存失败时保留草稿，卸载组件时取消请求，以及浏览器临时预览的现有语义。保持可见错误提示和当前页面交互。

使用可控制完成时机的 Promise 补充测试，覆盖连续排队保存、失败后重试、保存期间新增时长、切换材料或用户后旧读取结果才返回、存在排队任务时卸载组件、AI 请求取消，以及对象 URL 释放。断言面向可观察行为，不依赖 Hook 的内部结构。若基线测试失败，先排查，再判断是已有缺陷还是重构引入的回归。

## 文档与验证

每个新增函数、方法和类都添加简明的英文文档注释，说明有意义的输入、输出、副作用和失败行为。源代码注释保持英文，遵循全局 AGENTS.md。避免仅为减少文件行数而拆分，以及为假设中的未来需求增加抽象。

修改前运行相关现有测试；每次拆分后运行新增测试和受影响的回归测试。最终验证包括 UI 类型检查、`make test`、用于存储集成验证的 `make test-db`，以及 macOS Debug 的规范构建命令 `make build`。若检查发现改动影响 Apple 原生契约，再运行 `make test-apple`。未执行对应规范构建命令时，不宣称 Release 或 iOS 已通过验证。对写入同一原生构建目录的任务串行执行，并保留缓存。

交付时说明职责边界变化、实际测试结果、规范构建的目标与配置，以及未执行的验证。全仓库覆盖率必须通过真实覆盖率任务测量；仅增加测试数量不能证明覆盖率提高。

## 验收标准

- 拆分后，相关调用方和现有行为保持一致。
- 工作线程启动、请求分发、词库初始化和听力进度管理分别有明确的职责归属。
- 新增并发与失败场景测试，以及受影响的现有测试通过。
- macOS Debug 规范构建通过；若受阻，记录具体原因。
- 不删除用户数据或构建缓存。
